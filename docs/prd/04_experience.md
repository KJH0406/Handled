## 1. 기능 배경 및 목적

### 배경 / 문제

Handled의 공급은 "현지인이 가이드하는 경험"이다. 여행자는 (a) 무엇이 있는지 빠르게 훑고, (b) 마음이 가는 경험의 내용·가이드·후기를 충분히 확인한 뒤, (c) 다음 행동(예약 또는 관심 표명)으로 넘어가야 한다. 다만 현재는 **예약이 아직 열리지 않은 출시 전** 단계라, 전환 행동을 잃지 않으면서도 "곧 예약 가능"임을 알리고 관심 있는 사용자를 붙잡아 둘 장치가 필요하다.

### 목적 / 목표

- **탐색:** 도시·카테고리·검색어로 경험을 좁혀 원하는 것을 빠르게 찾게 한다.
- **확신:** 상세에서 활동 내용·일정 흐름·가이드 소개·후기·만남 장소·알아둘 점을 한 화면에서 제공해 "이 경험이 나에게 맞는지" 판단하게 한다.
- **출시 전 전환:** 예약 대신 **상담(알림) 신청**을 받아, 출시 시 연락할 수 있는 관심 사용자를 확보한다.

### 성공의 정의 · 비목표(Non-goals)

- **성공:** 여행자가 목록에서 경험을 찾아 상세로 들어가 내용을 확인하고, 관심 있는 경험에 상담 신청을 남긴다.
- **비목표(이번 범위 밖):** 실제 예약·결제·확정, 날짜/인원 선택 기반 재고·가격 산정, 경험 단위의 후기 수집, 경험별 맞춤 일정·사진·실제 만남 위치, 정렬·페이지네이션·즐겨찾기. (→ 섹션7)

> **현 상태 요약:** 상세의 "예약" 영역은 결제 흐름이 아니라 **상담 신청 영역**이다. 실제 예약 결제 경로는 출시 전이며 추후 checkout 문서에서 다룬다.

## 3. 핵심 사용자 플로우

**A. 탐색 (목록)**

1. 목록 진입(내비, 홈 추천 "전체 보기", 일정 결과의 추천 "전체 보기", 딥링크).
2. 도시·카테고리 필터 또는 검색어로 좁힌다 → 결과 수와 카드가 갱신된다.
3. 결과가 없으면 빈 상태 안내 → 필터 초기화로 복귀.
4. 카드를 선택해 상세로 이동.

**B. 확인 (상세)**

1. 상단에서 카테고리·기간·정원·제목·평점·가이드를 확인.
2. 사진, 활동 내용·포함 사항, 일정 흐름, 가이드 소개, 만남 장소, 알아둘 점, 후기를 차례로 본다.

**C. 출시 전 전환 (상담 신청)**

1. 상세의 예약 영역에서 "곧 예약 가능" 안내와 가격(1인 기준)을 본다.
2. 상담 신청을 누른다 → 비로그인이면 로그인 요구(→ [auth](./01_auth.md)) → 로그인 후 다시 신청.
3. 신청되면 확인 안내(연락받을 이메일 표기)가 뜨고, 이후 이 경험은 "신청함" 상태로 표시된다.

## 4. 화면별 기능 정의 및 정책

### 4.1 경험 목록 - `/experiences`

- **목적:** 전체 경험을 한 화면에서 탐색·필터·검색하게 한다.
- **진입 경로:** 전역 내비, 홈의 추천 경험 "전체 보기", 일정 결과의 추천 "전체 보기", 도시·카테고리·검색어가 담긴 딥링크.
- **구성 · 주요 기능:**
  - **인트로:** 키커·제목·소개문(소개문에 **전체 경험 수**가 들어간다).
  - **툴바:** 검색 입력(지우기 버튼 포함) · **도시 필터** · **취향 카테고리 필터**.
  - **결과 줄:** 현재 조건에 맞는 결과 수를 문장으로 표시(선택한 도시·휘향 카테고리를 문장에 반영). 필터·검색이 하나라도 적용 중이면 "필터 초기화" 제공.
  - **결과:** 경험 카드 그리드. 카드에는 사진·카테고리·제목·소요 시간·최대 인원·요약·가이드(사진·도시·이름)·1인 가격이 담기고, 누르면 상세로 이동.
  - **빈 상태:** 결과가 0개면 안내 제목·부연과 초기화 CTA.
- **정책 · 규칙:**
  - **딥링크 프리필:** 주소의 도시·카테고리·검색어 값으로 초기 필터·검색 상태를 채운다.
  - **도시 필터 범위:** 도시 필터는 일정 생성 시 입력 가능한 옵션을 제공한다.
  - **카테고리 필터:** 현재 운영 중인 경험들의 카테고리에서 자동으로 구성된다(없는 카테고리는 노출되지 않는다).
  - **검색 대상·방식:** 검색어는 경험 제목·요약·카테고리·가이드 이름·가이드 도시와 대조한다. 입력 직후가 아니라 잠깐 멈추면 반영된다(입력 중 끊김 방지).
  - **결과 수 문구:** 도시만/카테고리만/둘 다/둘 다 아님에 따라 문장이 달라진다.
  - **카드의 "곧 예약 가능" 배지:** : 곧 출시 임을 명시적으로 나타낸다.
- **상태별 표시:** 기본(전체) / 필터·검색 적용 / 빈 상태(0건) / (로딩은 즉시 렌더라 별도 표시 없음).

### 4.2 경험 상세 - `/experiences/[expId]`

- **목적:** 한 경험의 내용·가이드·후기·실무 정보를 충분히 제공해 결정과 (출시 전)상담 신청으로 잇는다.
- **진입 경로:** 목록 카드, 홈/일정 결과의 추천 카드, 공유·딥링크.
- **구성 · 주요 기능:**
  - **돌아가기:** 목록으로 돌아가는 경로(브레드크럼).
  - **헤더:** 카테고리 배지 / 기간·정원 요약 / 제목 / 가이드 평점·후기 수 / 가이드(사진·이름) 링크.
  - **사진 갤러리:** 대표 사진 + 보조 사진들.
  - **활동 내용:** "무엇을 하나" 설명 + 포함 사항 체크 목록.
  - **일정 흐름:** 단계별 일정(번호·제목·설명·사진)과 총 소요 시간.
  - **가이드 소개:** 사진·이름·(해당 시)인증 가이드 표시·연차/후기/평점 요약·소개글.
  - **만남 장소:** 지역(구/동) 표시와 안내 문구.
  - **알아둘 점:** 그룹 규모·소요 시간·진행 언어·취소 규정.
  - **후기:** 평점 헤딩과 후기 카드(이름·국가·별점·내용·날짜).
  - **예약 영역(상담 신청):** 섹션4.3. 참고
- **정책 · 규칙:**
  - **가격 표기:** 1인 기준 가격을 표시한다(통화·환산 규칙은 [foundation](./07_foundation.md)).
  - **후기의 출처:** 후기·평점·후기 수는 **경험이 아니라 가이드 단위**다. 같은 가이드의 다른 경험에는 같은 후기가 보이고, 헤딩 평점도 가이드 평점이다. → 섹션7 참고
  - **일정·갤러리·만남 장소는 대표 예시:** 일정 흐름은 카테고리 기준 표준 흐름이고, 갤러리는 경험·가이드 사진을 묶어 쓰며, 만남 장소는 정확한 지점이 아니라 지역 안내다("정확한 위치는 예약 후 공유"). → 섹션7 참고
- **상태별 표시:** 정상 / **없음(잘못된·없는 경험)** → 섹션4.4. 참고

### 4.3 예약 영역 = 상담(알림) 신청 (출시 전)

- **목적:** 예약이 열리기 전, 전환 행동을 잃지 않도록 관심 사용자를 상담 신청으로 받는다.
- **진입 경로:** 상세 우측(또는 하단) 고정 영역.
- **구성 · 주요 기능:** 1인 가격 / "곧 예약 가능" 안내 / 상담 신청 버튼 / 안내 문구. 신청 완료 시 "신청함" 상태와 확인 안내(연락받을 이메일 표기).
- **정책 · 규칙:**
  - **로그인 게이트:** 비로그인 사용자가 신청을 누르면 로그인 요구가 뜨고(→ [auth](./01_auth.md)), 로그인 후 다시 신청을 눌러 완료한다.
  - **신청 기록·중복 방지:** 로그인 사용자가 신청하면 그 사용자+경험 단위로 한 번 기록되어, 재방문 시 "신청함"으로 보이고 중복 신청되지 않는다.
  - **리드 도달 (중요):** 제출된 상담 신청은 현재 **운영팀에 전달되지 않는다**(실제 전달 경로 없음). → 섹션7 참고
  - **실제 예약 아님:** 이 영역은 날짜·인원 선택이나 결제가 아니며, 확정/거래가 발생하지 않는다(→ 추후 checkout 문서).
- **상태별 표시:** 미신청(신청 버튼) / 로그인 요구(모달) / 신청 완료(확인 안내) / 신청함(이후 재방문).

### 4.4 없는 경험 처리

- **목적:** 잘못된·삭제된 경험 주소에서 막다른 길을 만들지 않는다.
- **정책 · 규칙:** 존재하지 않는 경험 주소로 들어가면 안내 문구와 홈으로 가는 CTA를 보여준다(빈 상태). 페이지 제목도 "찾을 수 없음" 취지로 표기된다.
- **상태별 표시:** 없음(안내 + 홈 CTA).

| 필터·검색 결과 0건            | 빈 상태 안내 + 초기화 CTA.                                                       |
| 검색어 대소문자/언어 불일치   | 글자 단위 일치라 매칭되지 않을 수 있다.                                          |
| 사진 로드 실패                | 갤러리/카드가 카테고리 empty case 배경으로 대체되어 깨진 이미지를 보이지 않는다. |
| 비로그인으로 상담 신청        | 로그인 요구 → 로그인 후 다시 신청해야 완료(모달을 닫으면 미신청).                |
| 같은 경험에 재신청 시도       | 한 번만 기록되고 "신청함"으로 표시(중복 없음).                                   |
| 로그아웃/다른 사용자로 로그인 | 신청 상태는 사용자(이메일) 기준이라 사용자에 따라 다르게 보인다.                 |
| 잘못된/삭제된 경험 주소       | "없음" 안내 + 홈 CTA.                                                            |

## 7. TBD / 정책 공백

> 현재 비어 있는 기능 및 정책과 프로덕션 전환 시 결정이 필요한 항목. (결정권자 : CPO)

- **검토 필요 사항**
  1. **상담 리드가 운영팀에 도달하지 않음 (중요)** : 제출된 상담 신청이 운영팀에 전달되지 않음. 실제 수집 경로(접수·알림·후속 연락)가 필요.
  2. **신청 기록 관리 정책 필요** : 계정 기반 저장·동기화 정책 필요. 재신청은 어떻게 처리할지 결정 필요. 한번 신청하고 재신청 표시는 어떻게 하게할것인가(반려?, 취소?, 완료 후 재신청?)
  3. **MVP 포함 여부 결정 필요한 주요 기능 설명** (\* 아래 사항들은 결정에 따라 위 PRD 기능 요소 최신화 필요)
  - **후기(Review·평점·후기 수):** 경험 상세 페이지에 가이드에 대한 후기, 평점, 누적 후기 수를 노출하는 기능. 유저가 실제로 해당 경험에 대한 신뢰도와 만족도를 파악할 수 있도록 도와주는 주요 정보 요소이나, MVP 단계에서 포함할지(예: 후기 영역 표시 및 실제 등록/노출 기능 제공) 또는 제외할지 결정이 필요함.
  - **만남 장소(Meeting Point) 표시:** 경험마다 실제로 만나는 장소(정확한 위치, 지도, 약도 등)를 상세에 명시하는 기능. 사용자가 체험의 실제 시작 위치를 정확히 알 수 있게 하며, MVP에서 단순 텍스트(예: 주요 지역명) 표기로 충분할지, 상세 지도·정보까지 포함할지 아에 MVP 스펙에서 제외할지 결정 필요.
  - **취소 및 운영 정보의 고정 표기:** 각 경험마다 상이할 수 있는 취소 규정, 운영 시간, 기타 이용 조건(연령 제한 등)을 상세에 고정적으로 안내하는 기능. 표준 가이드라인(취소 가능 시점, 환불 규정 등)에 기반해 각 경험별 실제 정책을 표시하는 범위와 상세도를 MVP에서 어디까지 구현할지 확정 필요.

- **MVP 제외 (\* 향후 고도화)**
  1. **예약 출시 전** : 상세의 예약 영역이 실제 예약·결제가 아니라 상담 신청이다. 예약 기능을 제공하게 되면 날짜·인원 선택, 예약 가능 일정(요일·시간대·날짜별 정원), 재고/가격 확정, 결제·확정 경로를 함께 제공한다(→ 추후 checkout 문서).
  2. **상담 리드 수집 범위** : 현재 상담 신청은 연락받을 이메일만 표기한다. 이름·연락처·희망 날짜·인원·메시지 등 수집 항목 확장은 MVP에서는 제외하고, 향후 고도화 여지로 둔다.
