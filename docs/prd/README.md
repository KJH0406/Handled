# Handled - 기능 명세서

이 디렉토리는 **Handled**(신뢰할 수 있는 현지인이 호스팅하는 한국 로컬 경험 마켓플레이스 + AI 일정 플래너)의 기능 명세서를 **도메인별 분할 마크다운**으로 관리한다.

- **작성 기준** - 현재 구현된 동작을 사실대로 적고, 아직 구현되지 않았거나 정해지지 않은 정책은 각 문서의 **§7 TBD / 정책 공백**에 분리해 적는다.
- **독자: 개발자** - 각 문서는 "이 기능이 왜 있고(목적), 무엇이 완성인지(인수 조건)"를 명확히 전달한다.
- **제외 원칙:** DB 스키마, API 엔드포인트 설계, 내부 구현(파일/함수/컴포넌트명, 저장소 키 등) 같은 기술 디테일은 **본문에서 철저히 제외**한다. 동작은 _제품·정책_ 언어로 기술한다.

> **현 단계:** 백엔드 없는 **프로토타입**. 인증·결제·일정·상담 리드는 모두 모의(mock)이며 브라우저 저장소에만 존재한다. 이 전제가 여러 §7에 반복 등장한다.

화면은 도메인과 1:1이 아니며, 일부는 여러 도메인에 걸친다. 누락 방지를 위한 전수 매핑이다.

| 홈 `/`                                        | **home**       | planner · experience · stories       |

## 공통 용어집 (Glossary)

각 문서는 아래 용어를 동일한 의미로 사용한다.

| 용어                        | 정의                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------ |
| **게스트(Guest)**           | 로그인하지 않은 방문자. 탐색·상세 열람·일정 입력까지 가능.                                       |
| **가입 사용자(Member)**     | 로그인한 사용자. 일정 생성·저장·관리 가능.                                                       |
| **크레딧(Credit)**          | 일정 생성 단위로 설명되는 계정 자산. 신규 계정에 3개 부여. _현재 차감 로직 없음(§ 각 TBD 참조)._ |
| **가이드(Guide)**           | 경험을 호스팅하는 현지인. 도시·언어·스타일·평점·슈퍼호스트 속성 보유.                            |
| **경험(Experience)**        | 가이드가 제공하는 액티비티 상품. 13개 카테고리 중 하나.                                          |
| **스토리(Story)**           | 여행 콘텐츠(블로그) 글. 카테고리·토픽 태그 보유.                                                 |
| **일정 / 플랜(Plan)**       | 플래너가 생성한 다일차 여행 일정. 일자·시간대 슬롯·비용으로 구성.                                |
| **예약(Booking)**           | 결제 플로우로 진입하는 거래 단위(맞춤 견적 또는 경험).                                           |
| **관심사(Interest)**        | 일정 생성 입력으로 쓰이는 경험 카테고리 선택.                                                    |
| **출시 전(Pre-launch)**     | 경험 예약이 아직 비활성인 상태. 예약 대신 이메일 알림 신청을 받음.                               |
| **인증 게이트(Auth Gate)**  | 특정 행동(현재: 일정 생성) 직전에 로그인을 요구하는 지점.                                        |
| **로케일(Locale)**          | 언어/지역. 현재 `en`(기본)·`ko` 2종.                                                             |
| **모의(Mock) / 프로토타입** | 실제 백엔드·결제·인증이 없고 브라우저에서만 동작하는 현 구현 상태.                               |

## 작성 규약

- **문서 단위(페이지 기준):** 원칙적으로 한 문서는 한 페이지(라우트) 또는 긴밀한 라우트 그룹을 다룬다. 받는 사람이 그 페이지의 구현 요소를 한 곳에서 파악하게 한다. 다른 라우트의 기능은 그 라우트의 스펙에서 작성하고 여기서는 교차 참조만 한다. (전역 공통 동작은 `foundation`.)
- **메타 헤더:** 각 PRD는 제목 바로 아래에 **한 줄 요약**(독립 문장) + **2열 메타 표**(상태 · 작성 기준 · 관련 라우트 · 관련 PRD, 필요 시 범위 메모 · 참조)를 둔다. blockquote 한 문단에 이어붙이지 않는다.
- **대시 금지:** 본문에 엔대시나 엠대시를 쓰지 않는다. 무조건 하이픈(-)을 쓴다.
- **페르소나 & 유저 스토리 주어:** 사용자 *유형*이 실제로 다를 때만 페르소나를 나눈다. 현재 사용자는 **여행자(Traveler)** 한 종류이며, **로그인 여부는 *상태*이지 페르소나가 아니다.** 모든 유저 스토리 주어는 **"여행자로서"** 로 통일하고, 로그인·가입이 필요한 동작은 페르소나가 아니라 **전제·인수 조건**("비로그인 시 로그인을 요구한다")으로 표현한다. (호스트/가이드가 로그인 주체로 들어오면 그때 두 번째 페르소나를 추가.)
- **ID 체계:** 유저 스토리 `US-<도메인>-NN`, 인수 조건 `AC-<도메인>-NN`. AC는 대응 US ID를 괄호로 명시해 추적 가능하게 한다.
- **§4 화면별 정의** 는 화면 단위로 `목적 / 진입 경로 / 구성·주요 기능 / 정책·규칙 / 상태별 표시`를 반복한다.
- **§5 인수 조건** 은 `ID · 관련 US · 인수 조건` 표로 쓰고, 각 조건은 상황·동작·결과가 자연스럽게 이어지는 **한 문장**으로 표현한다(= "개발 완료 판정 기준"). 라벨이나 영어 키워드(Given/When/Then)는 쓰지 않는다.
- **§7 TBD** 는 (a) 미결정 정책 질문, (b) 프로토타입→프로덕션 갭을 모은다. 결정권자/기한은 placeholder로 둔다.
- **상태 표기:** ✅ 완료 · 🟡 초안/검토중 · ⬜ 예정.
