# 99. 알고리즘 / 생성 로직 검토 항목

플래너 일정 생성과 스토리 추천처럼 알고리즘·생성 로직이 관여하는 기능에서, 프로덕션 전환 시 정의가 필요한 기술 구현 검토 항목을 한곳에 모은다.

| 항목          | 내용                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------ |
| **상태**      | ⏸️ 보류 (\* 임시 기록용)                                                                   |
| **성격**      | 기술 구현 관점의 검토 항목 모음. 제품 PRD 본문(섹션4 정책)에서 분리해 임시로 보관          |
| **작성 기준** | 각 PRD 검토 중 도출된 미결 항목. 확인 후 PRD 본문에 둘지, 별도 기술 스펙으로 뺄지 결정     |
| **관련 PRD**  | [planner](./03_planner.md) · [stories](./05_stories.md) · [experience](./04_experience.md) |

> 아래 항목은 확인 후 각 PRD에서 다룰지, 기술 구현 영역으로 분리할지 결정이 필요하다. (결정권자: CPO)

---

## 1. 비용의 성격

비용은 추정치이며 실제 예약·확정 견적이 아니다. 프로덕션에서 AI·실데이터가 수치를 채우는 방식과 정확도 기준 정의가 필요하다.

- **관련:** [planner](./03_planner.md)
- **검토 포인트:** 기술 구현 관점이므로 해당 항목을 PRD 본문에서 제외할지 결정 필요.

## 2. 일정 실행 가능성 (영업시간·휴무)

생성된 일정은 장소의 영업시간, 정기 휴무일(예: 다수 궁·박물관 월요일 휴관), 공휴일, 계절 휴무를 반영해 닫힌 장소나 현실적으로 불가능한 동선을 배치하지 않아야 한다. 체류시간과 실제 이동시간, 지리적 군집(하루 동선이 지그재그가 되지 않도록)을 고려한다.

- **관련:** [planner](./03_planner.md)

## 3. 연령 적합성 필터링

미성년(청소년·아동)이 동반된 경우 성인 전용 콘텐츠(야간 유흥 등)를 자동 제외하는 등 연령에 맞는 장소·활동만 배치한다.

- **관련:** [planner](./03_planner.md)

## 4. 스토리 추천 매칭 (다음 스토리)

MVP에서는 스토리 상세 하단에 글의 컨셉(카테고리·토픽)과 맞는 다음 스토리(최대 3개)를 노출한다. 같은 카테고리·토픽을 우선하고 부족하면 최신 스토리로 보완하는 등, 다음 스토리 선정·매칭 기준 정의가 필요하다. 추후 글 유입을 서비스 이용 전환으로 잇기 위해 글 하단에 연관성 높은 경험을 함께 또는 대신 노출하는 방안을 검토할 경우, 글과 경험을 잇는 매칭 기준도 함께 정의한다.

- **관련:** [stories](./05_stories.md) · [experience](./04_experience.md)
