## 1. 기능 배경 및 목적

### 배경 / 문제
플래너는 Handled의 핵심 전환 지점이다. 그러나 첫 화면부터 회원가입을 강제하면 탐색 단계의 방문자가 이탈한다. 동시에, 생성된 일정을 다시 찾고(내 일정) 향후 크레딧·결제와 연결하려면 사용자를 식별할 최소한의 계정이 필요하다.

### 목적 / 목표
- **마찰 최소화:** 탐색·상세 열람·일정 입력까지는 인증 없이 허용한다.
- **적시 전환:** 가치가 확정되는 순간(일정 생성 직전)에만 가입/로그인을 요구하고, 인증 직후 원래 행동을 **끊김 없이 이어준다.**
- **계정 지속성:** 로그인 상태를 유지하고, 계정 정보(이메일·이름)와 **크레딧** 잔량을 한곳에서 보여준다.

### 성공의 정의 · 비목표(Non-goals)
- **성공:** 게스트가 일정 생성을 시도 → 1회 인증 → 동일 흐름으로 일정 결과 도달. 재방문 시 로그인 유지.
- **비목표(이번 범위 밖):** 실제 비밀번호 인증·이메일 검증·소셜 OAuth 연동·계정 관리(수정/삭제)·약관 동의 절차. (→ §7)

## 2. 유저 스토리 (User Story)

**페르소나:** **여행자(Traveler)** - Handled로 한국 여행을 계획·예약하는 사람. 로그인 여부는 *상태*(비로그인/로그인)이지 페르소나가 아니다. *(가이드/호스트는 현재 로그인 주체가 아니며 현 단계 제외 → §7)*

| ID | 스토리 |
|---|---|
| US-AUTH-01 | 여행자로서, 가입·로그인 없이 경험·스토리를 둘러보고 일정 입력까지 진행하고 싶다. |
| US-AUTH-02 | 여행자로서, 이메일로 빠르게 가입해 일정 생성을 시작하고 싶다. |
| US-AUTH-03 | 여행자로서, 소셜 계정으로 한 번에 로그인하고 싶다. |
| US-AUTH-04 | 여행자로서, 일정 생성 직전에 로그인 요구를 받더라도 인증 후 흐름이 끊기지 않고 그대로 생성으로 이어지길 원한다. |
| US-AUTH-05 | 여행자로서, 다시 방문하거나 새로고침해도 로그인 상태가 유지되길 원한다. |
| US-AUTH-06 | 여행자로서, 내 계정(이메일·이름)과 남은 크레딧을 확인하고 로그아웃할 수 있길 원한다. |
| US-AUTH-07 | 여행자로서, 비밀번호 표시/숨김을 토글하고 입력 오류를 즉시 이해하고 싶다. |

## 3. 핵심 사용자 플로우

**A. 가입 / 로그인 (직접 진입)**
1. 게스트가 `/sign-up` 또는 `/sign-in` 진입 → 폼 작성 → 제출.
2. 검증 통과 시 로그인 상태 전환 → **홈으로 이동.**
3. 이미 로그인 상태로 이 화면에 진입하면 → 즉시 홈으로 리다이렉트.

**B. 인증 게이트 (일정 생성 - 핵심 경로)**
1. 게스트가 플래너 위저드를 끝까지 채우고 **생성**을 누른다.
2. 비로그인이면 → **인증 요구 모달**이 뜬다(생성은 보류).
3. 모달에서 가입/로그인(또는 소셜) 완료 → 모달이 닫히고 **동일 입력으로 생성이 자동 재개** → 일정 결과로 이동.
4. 이미 로그인 상태면 모달 없이 즉시 생성. → 상세: [planner](./03_planner.md)

**C. 세션 유지 / 로그아웃**
1. 로그인 후 새로고침·재방문 → 로그인 상태 유지.
2. 전역 내비 계정 메뉴에서 로그아웃 → 게스트 상태로 전환.

## 4. 화면별 기능 정의 및 정책

### 4.1 로그인 - `/sign-in`
- **목적:** 기존 사용자가 로그인한다.
- **진입 경로:** 내비 "로그인" 링크, 가입 화면의 "로그인" 링크, 인증 모달의 모드 전환.
- **구성 · 주요 기능:** 로고·태그라인 / 이메일·비밀번호 입력(비밀번호 표시·숨김 토글) / 로그인·가입 버튼 / "비밀번호 찾기" 링크 / 소셜 로그인 버튼 묶음.
- **정책 · 규칙:**
  - **(프로토타입)** 이메일·비밀번호가 비어있지 않으면 통과한다. 비밀번호는 검증하지 않는다. → §7
  - 사용자 표시 이름은 이메일 아이디 부분에서 자동 생성한다.
  - 이미 로그인 상태면 이 화면을 보여주지 않고 홈으로 보낸다.
- **상태별 표시:** 기본 / 입력 오류(인라인 경고) / (해당 없음: 로딩·빈 상태).

### 4.2 회원가입 - `/sign-up`
- **목적:** 신규 사용자가 계정을 만든다.
- **진입 경로:** 내비/로그인 화면의 "가입" 링크, 인증 모달의 모드 전환.
- **구성 · 주요 기능:** 이름·이메일·비밀번호·비밀번호 확인 입력(표시·숨김 토글 공유) / 가입 버튼 / "이미 계정이 있나요? 로그인" 링크 / 소셜 버튼.
- **정책 · 규칙:**
  - 필수값(이름·이메일·비밀번호)이 모두 채워지고 **비밀번호와 확인이 일치**하면 가입 처리한다.
  - **(프로토타입)** 이메일 중복·형식·실재 여부를 검증하지 않으며, 가입 즉시 로그인 상태가 된다. → §7
  - 신규 계정에는 **크레딧 3개**가 부여된다(표시용).
  - 이미 로그인 상태면 홈으로 리다이렉트.
- **상태별 표시:** 기본 / 입력 오류(필수 누락·비밀번호 불일치).

### 4.3 인증 요구 모달 (일정 생성 게이트)
- **목적:** 비로그인 사용자가 일정 생성을 시도할 때 흐름을 끊지 않고 인증을 받는다.
- **진입 경로:** 플래너 위저드 §3-B 2단계에서 자동 노출.
- **구성 · 주요 기능:** 한 모달 안에서 **가입↔로그인 모드 전환** / 이메일·비밀번호 입력 / 소셜 버튼 / 맥락 카피(가입 모드 시 "가입하면 크레딧 N개" 안내).
- **정책 · 규칙:**
  - 인증 완료 시 모달이 닫히고 **원래 시도하던 일정 생성이 자동으로 이어진다.**
  - 모달을 닫으면(오버레이 클릭·ESC·닫기 버튼) 생성은 진행되지 않고 입력은 초기화된다.
  - 기본 진입 모드는 *가입*이다(신규 전환 우선).
- **상태별 표시:** 기본 / 입력 오류 / 닫힘.

### 4.4 전역 내비 계정 메뉴
- **목적:** 어디서나 로그인 진입과 계정 동작을 제공한다.
- **구성 · 주요 기능:**
  - **게스트:** "로그인" 링크 + 계정 아이콘.
  - **로그인:** 계정 드롭다운 - 이름·이메일 표시, "내 일정", "도움말", "로그아웃".
- **정책 · 규칙:**
  - 로그인 여부가 **확정되기 전(초기 로드)에는** 로그인/계정 UI를 깜빡이지 않도록 노출을 보류한다.
  - 드롭다운은 외부 클릭·ESC·페이지 이동 시 닫힌다.
- **상태별 표시:** 상태 미확정(노출 보류) / 게스트 / 로그인.

### 4.5 계정 대시보드 (`/my-plans`) - 이관됨
`/my-plans` 페이지(프로필·크레딧 카드·탭·저장 일정 목록) 전체는 [06_my-plans](./06_my-plans.md)에서 다룬다. 인증 관점의 연계만 적는다.
- 로그인 사용자의 계정 정보(이메일·이름)와 **크레딧 잔량**이 이 페이지에 표시된다(크레딧은 가입 시 부여, 차감 없음 → §7).
- 비로그인 접근 시의 노출·접근 정책은 §7.

## 5. 인수 조건 (Acceptance Criteria)

> 각 조건은 "이 동작이 이렇게 되면 기능 완성"을 판정하는 기준이다. 한 문장으로 자연스럽게 읽히도록 쓰고, 대응 유저 스토리를 함께 표기한다.

| ID | 관련 US | 인수 조건 (완성 기준) |
|---|---|---|
| AC-AUTH-01 | US-AUTH-01 | 비로그인 상태에서도 가이드·경험·스토리 목록/상세와 플래너 입력까지 로그인 요구 없이 모두 이용할 수 있다. |
| AC-AUTH-02 | US-AUTH-02 | 가입 폼에 이름·이메일·비밀번호·확인을 채워 제출하면, 비밀번호가 일치할 때 로그인 상태로 홈으로 이동하고, 일치하지 않으면 인라인 오류가 보조기술이 인지할 수 있는 형태로 표시된다. |
| AC-AUTH-03 | US-AUTH-03 | 로그인/가입 화면이나 인증 모달에서 소셜 버튼을 선택하면, 즉시 로그인 상태가 되어 의도한 다음 단계(홈 또는 생성)로 진행된다. |
| AC-AUTH-04 | US-AUTH-04 | 비로그인으로 위저드를 끝낸 상황에서 생성을 누르면, 인증 모달이 뜨고 인증 후 동일 입력으로 일정 생성이 자동으로 이어진다. |
| AC-AUTH-05 | US-AUTH-04 | 인증 모달이 열린 상태에서 닫기·ESC·오버레이 클릭으로 닫으면, 일정은 생성되지 않고 입력이 초기화된다. |
| AC-AUTH-06 | US-AUTH-05 | 로그인한 뒤 새로고침하거나 재방문해도 로그인 상태가 유지된다. |
| AC-AUTH-07 | US-AUTH-06 | 로그인 상태에서 계정 메뉴를 열면 이름·이메일과 '내 일정'·'로그아웃'이 보이고, 로그아웃하면 게스트 상태로 전환된다. |
| AC-AUTH-08 | US-AUTH-06 | 신규 가입 시 계정에 크레딧 3개가 부여된다(잔량을 보여주는 화면은 [my-plans](./06_my-plans.md)). |
| AC-AUTH-09 | US-AUTH-07 | 인증 입력 폼의 모든 입력은 라벨과 연결되고, 오류는 보조기술이 인지할 수 있게 전달되며, 비밀번호 표시/숨김 상태가 보조기술에 노출된다. (속성 수준 기준은 [foundation](./07_foundation.md) · `/DESIGN.md`) |
| AC-AUTH-10 | US-AUTH-01 | 이미 로그인된 상태에서 `/sign-in` 또는 `/sign-up`에 직접 진입하면 홈으로 리다이렉트된다. |

## 6. 예외 처리 & 엣지 케이스

| 상황 | 기대 동작 |
|---|---|
| 빈 값/공백만 입력 후 제출 | "필수 입력" 오류를 인라인 알림으로 표시, 진행 차단. |
| (가입) 비밀번호 ≠ 확인 | "비밀번호 불일치" 오류 표시, 진행 차단. |
| 입력 수정 시 | 기존 오류 메시지는 즉시 사라진다. |
| 이미 로그인 상태로 로그인/가입 화면 진입 | 홈으로 리다이렉트(화면 미노출). |
| 초기 로드(로그인 여부 미확정) | 로그인/계정 UI 노출을 보류해 깜빡임을 방지. |
| 브라우저 저장 차단(시크릿/권한 거부) | 세션이 유지되지 않아 매 방문 게스트로 시작(동작 자체는 유지). |
| 동일 이메일로 재가입/재로그인 | 계정 개념이 없어 항상 새 세션으로 덮어쓴다. → §7 |
| 크레딧이 0인 사용자 | 현재 생성 차단 로직 없음(크레딧 차감 자체가 없음). → §7 |
| 이메일 복사 시 클립보드 차단 | 무동작(상태 변화 없음). |
| 인증 모달을 닫았다가 다시 생성 시도 | 다시 모달이 뜨고 정상 흐름 재개. |

## 7. TBD / 정책 공백

> 아래는 **현재 프로토타입에서 비어 있는 정책**과 **프로덕션 전환 시 결정해야 할 항목**이다. (결정권자·기한: _TBD_)

1. **실제 인증 부재** - 비밀번호를 검증하지 않고, 임의 이메일로 누구나 로그인된다. → 실제 계정·비밀번호 정책·이메일 인증·중복 가입 처리 정의 필요.
2. **소셜 로그인은 모의** - 실제 OAuth가 아니라 데모 계정으로 처리된다. → 제공자 연동 범위(Google/Facebook/LINE/Apple), 동의 스코프, 기존 계정 연결 정책.
3. **크레딧 미차감 (중요)** - 일정 생성 시 크레딧이 **차감되지 않고**, 잔량 검증·0일 때 차단도 없다. 사실상 무제한 생성 가능. → (a) 차감 규칙(생성 1건 = ?), (b) 소진 시 UX, (c) 충전/구매 정책. *현재 "충전" 버튼은 동작하지 않음.*
4. **일정-계정 비연동 (중요)** - 저장된 일정이 계정에 귀속되지 않고 기기/브라우저에 묶인다(로그아웃하거나 다른 사용자로 로그인해도 동일 목록이 보임). → 계정 기반 저장·동기화·기기 간 연속성 정책.
5. **게스트의 `/my-plans` 접근** - 비로그인도 대시보드에 접근 가능(게스트 표기). → 로그인 강제 여부 등 접근 정책 확정.
6. **비밀번호 찾기 부재** - "비밀번호 찾기"는 비활성 링크. → 재설정 플로우.
7. **계정 관리 화면 부재** - 프로필 수정·이메일/비밀번호 변경·계정 삭제 화면이 없다.
8. **약관/개인정보 동의 부재** - 가입 시 약관·개인정보 동의 절차가 없다. → 법적 동의 게이트 필요.
9. **호스트/가이드 계정 부재** - 가이드는 데이터로만 존재하며 로그인 주체가 아니다. → 호스트 온보딩·인증이 별도 트랙으로 필요한지 결정.
10. **세션 정책** - 만료·다중 기기·강제 로그아웃 정책 미정.
