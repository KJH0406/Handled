## 1. 기능 배경 및 목적

### 배경 / 문제

플래너는 Handled의 핵심 전환 지점이다. 그러나 첫 화면부터 회원가입을 강제하면 탐색 단계의 방문자가 이탈한다. 동시에, 생성된 일정을 다시 찾고(내 일정) 향후 크레딧·결제와 연결하려면 사용자를 식별할 최소한의 계정이 필요하다.

### 목적 / 목표

- **마찰 최소화:** 탐색·상세 열람·일정 입력까지는 인증 없이 허용한다.
- **적시 전환:** 가치가 확정되는 순간(일정 생성·경험 상담 신청 등)에만 가입/로그인을 요구하고, 인증 직후 원래 행동을 **끊김 없이 이어준다.**
- **계정 지속성:** 로그인 상태를 유지하고, 계정 정보(이메일·이름)와 **크레딧** 잔량을 한곳에서 보여준다.

### 성공의 정의 · 비목표(Non-goals)

- **성공:**
  - 게스트가 인증 없이 일정 입력, 경험 탐색 및 상세 열람, 스토리 탐색 및 상세 열람까지 마찰 없이 진행한다.
  - 로그인이 필요한 행동(일정 생성, 경험 상담 신청 등)에 이르면 1회 인증으로 흐름이 끊기지 않고 원래 행동으로 이어진다(대표 경로: 일정 생성 → 일정 결과 도달).
  - 재방문, 새로고침 시 로그인이 유지되고, 계정 정보와 크레딧을 어디서나 확인할 수 있다.
- **비목표(이번 범위 밖):** 실제 비밀번호 인증·이메일 검증·소셜 OAuth 연동·계정 관리(수정/삭제)·약관 동의 절차. (→ 섹션7 참고)

## 3. 핵심 사용자 플로우

**A. 가입 / 로그인 (직접 진입)**

1. 게스트가 `/sign-up` 또는 `/sign-in` 진입 → 폼 작성 → 제출.
2. 검증 통과 시 로그인 상태로 전환되고, **로그인 직전에 보던 페이지로 돌아간다(직전 페이지를 알 수 없으면 홈으로 리다이렉트).**
3. 이미 로그인 상태로 이 화면에 진입하면 → 즉시 홈으로 리다이렉트.

**B. 인증 게이트 (전역 패턴)**

인증 게이트는 비로그인 사용자가 로그인이 필요한 행동을 시도할 때 흐름을 끊지 않고 **같은 인증 요구 모달**로 인증을 받는 공통 패턴이다. 특정 화면 전용이 아니라 여러 지점에서 재사용된다.

> **인증 게이트 발동 지점** _(새 인증 게이트가 추가되면 이 목록을 최신 상태로 유지한다.)_
>
> - **일정 생성** (`/plan/new`) - 인증 후 동일 입력으로 생성이 **자동 재개**된다. (핵심 경로, 아래 상세)
> - **경험 상담 신청** (경험 상세) - 인증 후 신청 버튼을 **다시 눌러야** 한다. → 상세: [experience](./04_experience.md)

**핵심 경로 - 일정 생성:**

1. 게스트가 플래너 위저드를 끝까지 채우고 **생성**을 누른다.
2. 비로그인이면 → **인증 요구 모달**이 뜬다(생성은 보류).
3. 모달에서 가입/로그인(또는 소셜) 완료 → 모달이 닫히고 **동일 입력으로 생성이 자동 재개** → 일정 결과로 이동.
4. 이미 로그인 상태면 모달 없이 즉시 생성. → 상세: [planner](./03_planner.md)

**C. 세션 유지 / 로그아웃**

1. 로그인 후 새로고침·재방문 → 로그인 상태 유지.
2. 전역 내비 계정 메뉴에서 로그아웃 → 게스트 상태로 전환.

## 4. 화면별 기능 정의 및 정책

### 4.1 로그인 - `/sign-in`

- **목적:** 기존 사용자가 로그인한다.
- **진입 경로:** 내비 "로그인" 링크, 가입 화면의 "로그인" 링크, 인증 모달의 모드 전환.
- **구성 · 주요 기능:**
  - 서비스 타이틀(Handled), 태그라인 (ex. **Korea Your Way**)
  - 이메일·비밀번호 입력(비밀번호 표시·숨김 토글)
  - 로그인·가입 버튼
  - "비밀번호 찾기" 링크
  - 소셜 로그인 버튼 묶음
- **정책 · 규칙:**
  - 이메일과 비밀번호는 각각 올바른 형식을 만족해야 한다.
    - 이메일: 올바른 이메일 주소 형식(`someone@email.com`)이어야 하며, 그렇지 않으면 input 하위에 "올바른 이메일 주소를 입력해 주세요" 등 벨리데이션 메시지를 노출한다.
    - 비밀번호: 최소 8자 이상이어야 하며, 부족하면 "비밀번호는 8자 이상 입력해 주세요" 등 벨리데이션 메시지를 노출한다.
  - 사용자 표시 이름은 회원 가입 시 입력한 `Name` 값으로 표시한다.
  - 이미 로그인 상태면 이 화면을 보여주지 않고 홈으로 보낸다.
- **상태별 표시:** 기본 / 입력 오류(인라인 경고) / (해당 없음: 로딩·빈 상태).

### 4.2 회원가입 - `/sign-up`

- **목적:** 신규 사용자가 계정을 만든다.
- **진입 경로:** 내비/로그인 화면의 "가입" 링크, 인증 모달의 모드 전환.
- **구성 · 주요 기능:**
  - 이름·이메일·비밀번호·비밀번호 확인 입력(표시·숨김 토글 공유)
  - 가입 버튼
  - "이미 계정이 있나요? 로그인" 링크
  - 소셜 로그인 버튼 묶음
- **정책 · 규칙:**
  - 필수값(이름·이메일·비밀번호)이 모두 채워지고 **비밀번호와 확인이 일치**하면 가입 처리한다.
  - 가입 즉시 로그인 상태가 된다.
  - 신규 계정에는 **크레딧 3개**가 부여된다.
  - 이미 로그인 상태면 홈으로 리다이렉트.
- **상태별 표시:** 기본 / 입력 오류(필수 누락·비밀번호 불일치).

### 4.3 인증 요구 모달 (인증 게이트 공통 모달)

- **목적:** 비로그인 사용자가 로그인이 필요한 행동을 시도할 때 흐름을 끊지 않고 인증을 받는다. 게이트 발동 지점 전체에서 같은 모달을 쓴다(섹션 3-B 참고).
- **진입 경로:** 인증 게이트 발동 시 자동 노출(섹션 3-B 목록 참고).
- **구성 · 주요 기능:**
  - 한 모달 안에서 **가입↔로그인 모드 전환**
  - 이메일·비밀번호 입력
  - 소셜 버튼
  - 맥락 카피(가입 모드 시 "가입하면 크레딧 N개" 안내).
- **정책 · 규칙:**
  - 인증 완료 시 모달이 닫힌다. 이후 동작은 게이트별로 다르다(일정 생성: 생성 자동 재개 / 경험 상담 신청: 신청 버튼 재클릭). 각 후속 동작은 해당 화면 정의를 따른다.
  - 모달을 닫으면(오버레이 클릭·닫기 버튼) 생성은 진행되지 않고 입력은 초기화된다.
  - 기본 진입 모드는 *가입*이다(신규 전환 우선).
- **상태별 표시:** 기본 / 입력 오류 / 닫힘.

### 4.4 전역 내비 계정 메뉴

- **목적:** 어디서나 로그인 진입과 계정 동작을 제공한다.
- **구성 · 주요 기능:**
  - **게스트:** "로그인" 버튼
  - **로그인:** 계정 드롭다운 - 이름·이메일 표시, "내 일정", "도움말"(현재 비활성), "로그아웃".
- **정책 · 규칙:**
- **상태별 표시:** -.

### 4.5 계정 대시보드 (`/my-plans`) - 이관됨

`/my-plans` 페이지(프로필·크레딧 카드·탭·저장 일정 목록) 전체는 [06_my-plans](./06_my-plans.md)에서 다룬다. 인증 관점의 연계만 적는다.

- 로그인 사용자의 계정 정보(이메일·이름)와 **크레딧 잔량**이 이 페이지에 표시된다(크레딧은 가입 시 부여, 차감 없음 → 섹션7 참고).
- 비로그인 접근 시의 노출·접근 정책은 섹션7 참고.

| AC-AUTH-05 | US-AUTH-04 | 인증 모달이 열린 상태에서 닫기 버튼이나 오버레이 클릭으로 닫으면, 일정은 생성되지 않고 입력이 초기화된다.                                                                                                                |

| AC-AUTH-08 | US-AUTH-06 | 신규 가입 시 계정에 크레딧 3개가 부여된다(잔량을 보여주는 화면은[my-plans](./06_my-plans.md)).                                                                                                                           |

## 6. 예외 처리 & 엣지 케이스

| 상황                                     | 기대 동작                                                          |
| ---------------------------------------- | ------------------------------------------------------------------ |
| 빈 값/공백만 입력 후 제출                | "필수 입력" 오류를 인라인 알림으로 표시, 진행 차단.                |
| (가입) 비밀번호 ≠ 확인                   | "비밀번호 불일치" 오류 표시, 진행 차단.                            |
| 입력 수정 시                             | 기존 오류 메시지는 즉시 사라진다.                                  |
| 이미 로그인 상태로 로그인/가입 화면 진입 | 홈으로 리다이렉트(화면 미노출).                                    |
| 브라우저 저장 차단(시크릿/권한 거부)     | 세션이 유지되지 않아 매 방문 게스트로 시작(동작 자체는 유지).      |
| 동일 이메일로 재가입                     | "이미 가입된 계정" 오류를 표시, 진행 차단.                         |
| 크레딧이 0인 사용자                      | 현재 일정 생성 차단 로직 없음(크레딧 차감 자체가 없음). 섹션7 참고 |
| 인증 모달을 닫았다가 다시 생성 시도      | 다시 모달이 뜨고 정상 흐름 재개.                                   |

## 7. TBD / 정책 공백

> 현재 비어 있는 기능 및 정책과 프로덕션 전환 시 결정할 항목. (결정권자 : CPO)

1. **실제 인증 로직 정의 필요** : 실제 계정·비밀번호 정책·이메일 인증·중복 가입 처리 정의 필요.
2. **소셜 로그인 연동 범위 결정 필요** : 제공자 연동 범위(Google/Facebook/LINE/Apple), 동의 스코프, 기존 계정 연결 정책(\* 이메일로 기가입했을 시).
3. **크레딧 잔량 검증 (중요)** - 일정 생성 시 0일 때 유저 플로우 설계 필요. 충전/구매 정책 정의가 필요하며, 기획 방향성에 따라 크래딧 충전, 결제 UI/UX 설계 필요.
4. **계정 관리 화면 부재** - 프로필 수정·이메일/비밀번호 변경·계정 삭제 화면이 없다.
5. **약관/개인정보 동의 부재** - 가입 시 약관·개인정보 동의 절차가 없다. → 법적 동의 게이트 필요.
