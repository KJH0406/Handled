# 06. 내 일정 (My Plans / 계정 대시보드)

**한 줄 요약:** 한 화면에서 계정 정보(이메일·이름)와 크레딧을 보여주고, 저장한 일정을 예정/지난으로 나눠 열기·편집·삭제하게 하며, 저장 경험 자리(출시 전)를 마련한다.

| 항목 | 내용 |
| --- | --- |
| **상태** | 🟡 초안(검토 요청) |
| **작성 기준** | 현재 구현된 동작 기준 (미구현·정책 공백은 §7에 분리) |
| **관련 라우트** | `/my-plans` |
| **범위 메모** | 계정 모델·크레딧 부여·로그인 자체는 [auth](./01_auth.md)가, 일정 생성·저장 동작은 [planner](./03_planner.md)가 소유한다. 이 문서는 **대시보드 화면의 표시·관리 동작**을 다룬다. 저장 경험 탭은 출시 전(→ §7). |
| **관련 PRD** | [auth](./01_auth.md)(계정·크레딧·세션) · [planner](./03_planner.md)(일정 생성·저장·열기/편집) · [experience](./04_experience.md)(경험 둘러보기) · [foundation](./07_foundation.md)(날짜·복사·접근성) |

## 1. 기능 배경 및 목적

### 배경 / 문제
일정을 생성·저장한 뒤에는 "내가 만든 것들을 다시 찾고 관리할 곳"이 필요하다. 동시에 사용자는 자기 계정 정보와 남은 크레딧을 한곳에서 확인하고 싶어 한다. 내 일정 화면은 이 둘(계정 + 저장물)을 모은 개인 대시보드다.

### 목적 / 목표
- **계정 한눈 보기:** 이메일·이름과 남은 크레딧을 한곳에서 확인한다.
- **저장물 관리:** 저장한 일정을 예정/지난으로 나눠 보고, 열기·편집·삭제한다.
- **다음 행동 유도:** 새 일정 만들기와 (출시 후)저장 경험으로 자연스럽게 잇는다.

### 성공의 정의 · 비목표(Non-goals)
- **성공:** 사용자가 대시보드에서 자기 정보·크레딧을 확인하고, 저장한 일정을 찾아 열거나 정리한다.
- **비목표(이번 범위 밖):** 크레딧 충전·결제, 일정 입력 사후 편집(날짜·인원 등 수정 후 재생성), 저장 경험 보관, 프로필 수정(이름·이메일·사진), 계정 삭제. (→ §7)

## 3. 핵심 사용자 플로우

**A. 대시보드 확인**
1. 내 일정 진입(내비 계정 메뉴, 일정 저장 후 이동, 딥링크).
2. 상단에서 이메일·이름·크레딧을 확인(이메일 복사 가능).

**B. 저장 일정 관리**
1. "일정" 탭에서 예정/지난 목록을 본다.
2. 일정을 눌러 결과로 열거나, 행 메뉴에서 편집(=열기)·삭제를 선택.
3. 삭제는 확인 모달을 거쳐 실행되고 목록이 갱신된다.

**C. 다음 행동**
1. "새 일정 만들기"로 위저드 진입(→ [planner](./03_planner.md)).
2. "경험" 탭에서 경험 둘러보기로 이동(→ [experience](./04_experience.md)).

## 4. 화면별 기능 정의 및 정책

### 4.1 계정 헤더 (프로필)
- **목적:** 누구의 대시보드인지와 연락처(이메일)를 보여준다.
- **구성 · 주요 기능:** 기본 아바타(아이콘) / 이메일(크게) / 이메일 복사 버튼(복사됨 피드백) / 이름.
- **정책 · 규칙:**
  - **로그인:** 로그인 사용자의 이메일·이름을 표시한다(계정 모델은 [auth](./01_auth.md)).
  - **비로그인:** 게스트용 자리표시 이름·이메일을 보여준다(실제 계정 아님). → §7
  - **이메일 복사:** 클립보드에 복사하고 잠시 "복사됨"을 표시한다. 클립보드를 못 쓰면 아무 변화도 주지 않는다(→ [foundation](./07_foundation.md)).
- **상태별 표시:** 로그인(실제 정보) / 비로그인(자리표시) / 복사됨(임시 피드백).

### 4.2 크레딧 카드
- **목적:** 남은 일정 생성 크레딧을 보여주고 충전 진입을 마련한다.
- **구성 · 주요 기능:** "크레딧" 라벨 / 잔량 값 / "충전" 버튼.
- **정책 · 규칙:**
  - 잔량은 계정 크레딧을 따른다(신규 계정 3개 부여 → [auth](./01_auth.md)). 비로그인 시 0으로 보인다.
  - **충전 버튼은 현재 동작하지 않는다**(추후 제공). → §7
  - **크레딧은 생성 시 차감되지 않는다**(잔량은 표시용). → §7 ([auth](./01_auth.md)·[planner](./03_planner.md)와 공유)
- **상태별 표시:** 잔량 표시(충전 버튼은 비동작).

### 4.3 탭 - 일정 / 경험
- **목적:** 저장물을 종류별로 나눠 보여준다.
- **구성 · 주요 기능:** "일정"(저장 일정 수 표시) · "경험" 두 탭.
- **정책 · 규칙:** 기본 탭은 "일정". 탭 전환은 화면 안에서 즉시 이뤄진다.
- **상태별 표시:** 일정 탭 / 경험 탭.

### 4.4 일정 탭 - 저장 일정 목록
- **목적:** 저장한 일정을 예정/지난으로 나눠 관리한다.
- **진입 경로:** 일정 저장 후 이동, 내비 계정 메뉴.
- **구성 · 주요 기능:**
  - **새 일정 만들기 카드:** 위저드로 진입(→ [planner](./03_planner.md)).
  - **예정 / 지난 구획:** 각 구획에 일정 행 목록.
  - **일정 행:** 도시 머리글자 원형 아이콘(도시별 색) · 이름 · 날짜 범위 · "도시 · N일" · 행 메뉴(편집·삭제).
  - **빈 상태:** 저장 일정이 0개면 안내(제목·부연).
- **정책 · 규칙:**
  - **저장된 것만 노출:** 생성만 하고 저장하지 않은 일정은 목록에 나오지 않는다(저장 동작은 [planner](./03_planner.md)).
  - **예정/지난 구분:** 종료일이 오늘 이후면 예정, 지났으면 지난으로 분류한다(오늘은 사용자 기기 날짜 기준). 예정은 시작일 빠른 순, 지난은 시작일 늦은 순으로 정렬.
  - **열기·편집:** 행을 누르거나 메뉴의 "편집"을 누르면 **둘 다 일정 결과 화면을 연다.** 현재 "편집"은 입력(날짜·인원 등)을 고쳐 재생성하는 기능이 아니다. → §7
  - **삭제:** 메뉴의 "삭제"는 확인 모달을 띄우고, 확인하면 일정을 지우고 목록을 갱신한다.
  - **행 메뉴:** 외부 클릭·ESC로 닫힌다.
- **상태별 표시:** 로딩 / 빈 상태(0건) / 예정·지난 목록 / 삭제 확인 모달.

### 4.5 경험 탭 - 저장 경험 (출시 전)
- **목적:** 저장한 경험을 모아 볼 자리를 마련한다(아직 미제공).
- **구성 · 주요 기능:** 안내 자리표시(제목·부연)와 "경험 둘러보기" CTA(→ [experience](./04_experience.md)).
- **정책 · 규칙:** 현재 경험 저장 기능이 없어 항상 자리표시 상태다. → §7
- **상태별 표시:** 자리표시(둘러보기 CTA).

## 6. 예외 처리 & 엣지 케이스

| 상황 | 기대 동작 |
|---|---|
| 저장 일정 0개 | 일정 탭에 빈 상태 안내, 새 일정 만들기 카드는 유지. |
| 예정만 있고 지난 없음(또는 반대) | 해당 구획만 표시된다. |
| 비로그인으로 접근 | 게스트 자리표시 프로필·크레딧 0으로 열린다(차단 없음). → §7 |
| 클립보드 차단(시크릿/권한) | 복사 동작이 무시되고 상태 변화 없음. |
| 충전 버튼 클릭 | 현재 아무 동작도 하지 않는다. → §7 |
| 행 메뉴의 "편집" | 입력 수정이 아니라 결과 열기로 동작한다. → §7 |
| 삭제 모달에서 취소 | 일정은 그대로 유지된다. |
| 다른 기기/브라우저로 접근 | 저장 일정이 보이지 않는다(기기 종속 저장). → §7 |
| 로그아웃 후 접근 | 저장 일정은 계정이 아니라 기기에 묶여 있어 그대로 보인다(프로필만 게스트로 표시). → §7 |
| 경험 탭 진입 | 저장 경험 기능이 없어 항상 자리표시가 보인다. → §7 |

## 7. TBD / 정책 공백

> 현재 비어 있는 정책과 프로덕션 전환 시 결정할 항목. (결정권자·기한: _TBD_)

1. **일정-계정 비연동 (중요)** - 저장 일정이 계정이 아니라 기기/브라우저에 묶인다. 로그아웃하거나 다른 사용자로 로그인해도 같은 목록이 보이고, 다른 기기에서는 보이지 않는다. 계정 기반 저장·동기화 정책 필요. ([auth](./01_auth.md)·[planner](./03_planner.md) §7과 공유)
2. **게스트 접근 정책** - 비로그인도 대시보드에 접근해 자리표시 프로필과 저장 일정을 본다. 로그인 강제 여부·게스트 표시 정책 확정 필요. ([auth](./01_auth.md) §7과 공유)
3. **크레딧 충전·차감 부재 (중요)** - 충전 버튼이 동작하지 않고, 생성 시 차감도 없어 잔량이 사실상 표시용이다. 충전/구매·차감·소진 UX 정책 필요. ([auth](./01_auth.md)·[planner](./03_planner.md) §7과 공유)
4. **일정 입력 사후 편집 부재** - "편집"이 결과 열기로 동작하며, 입력(날짜·인원 등)을 고쳐 재생성하는 경로가 없다. ([planner](./03_planner.md) §7과 공유)
5. **저장 경험 미구현** - 경험 탭이 자리표시뿐이다. 경험 저장·표시 기능 필요(예약 출시와 연계 → [experience](./04_experience.md)).
6. **프로필 관리 부재** - 이름·이메일·사진 수정과 계정 삭제 화면이 없다(아바타는 고정 아이콘). ([auth](./01_auth.md) §7과 공유)
7. **예정/지난 기준의 단순함** - 종료일과 기기 날짜만으로 구분하며, 시간대·진행 중 상태 등을 다루지 않는다. 분류 기준 정교화 필요.
