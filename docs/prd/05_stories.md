# 05. 스토리 (Stories)

여행자가 한국 여행 콘텐츠(블로그 글)를 카테고리·토픽 태그로 둘러보고, 한 글을 읽은 뒤 다음 스토리로 이어 읽으며, 여행 영감을 얻게 한다.

| 항목            | 내용                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------ |
| **상태**        | 🟡 초안(검토 요청)                                                                               |
| **작성 기준**   | 현재 구현된 동작 기준 (미구현·정책 공백은 섹션7에 분리)                                          |
| **관련 라우트** | `/stories`(목록) · `/stories/[storyId]`(상세)                                                    |
| **범위 메모**   | 콘텐츠 읽기 전용 도메인. 댓글·좋아요·공유 같은 참여 기능은 현 단계 제외(→ 섹션7). 단, 뉴스레터 구독은 제공한다(→ 섹션4.4). |

## 1. 기능 배경 및 목적

### 배경 / 문제

경험·일정만으로는 여행 동기가 충분히 자극되지 않는다. 여행자는 "무엇을, 왜, 어떻게" 즐기는지에 대한 맥락과 영감을 원한다. 스토리는 현지 시선의 읽을거리로 이 빈자리를 채우고, 둘러보다 자연스럽게 경험·일정으로 관심이 번지게 하는 진입 콘텐츠다.

### 목적 / 목표

- **영감·맥락 제공:** 동네·음식·문화·자연 등 주제별 글로 여행 결정을 돕는 맥락을 준다.
- **가벼운 탐색:** 카테고리와 토픽 태그로 관심 주제만 빠르게 골라 읽게 한다.
- **다음 스토리로 잇기:** 한 글을 다 읽으면 컨셉이 맞는 다음 스토리로 자연스럽게 이어 읽게 해 탐색을 이어 간다.

### 성공의 정의 · 비목표(Non-goals)

- **성공:** 여행자가 목록에서 관심 주제를 골라 글을 열고, 끝까지 읽은 뒤 다음 스토리로 이어 읽는다.
- **비목표(이번 범위 밖):** 글 작성·관리(CMS), 댓글·좋아요·북마크, 실제 공유, 본문 내 실제 사진/미디어, 검색·페이지네이션, 글 하단 경험 연계. (→ 섹션7)

## 3. 핵심 사용자 플로우

**A. 탐색 (목록)**

1. 목록 진입(내비, 홈의 스토리 진입, 딥링크).
2. 주요 글·최신 글을 먼저 본다.
3. 카테고리 또는 토픽 태그로 좁힌다 → 글 그리드가 갱신된다.
4. 결과가 없으면 빈 상태 안내 → 필터 초기화로 복귀.
5. 글 카드를 선택해 상세로 이동.

**B. 읽기 (상세)**

1. 제목·카테고리·날짜·읽는 시간과 요약을 본 뒤 본문을 읽는다.
2. 하단 토픽 태그를 눌러 같은 주제의 목록으로 이동.
3. 글 컨셉과 맞는 다음 스토리로 이어 읽는다.

## 4. 화면별 기능 정의 및 정책

### 4.1 스토리 목록 - `/stories`

- **목적:** 전체 글을 주요/최신/카테고리/토픽으로 둘러보게 한다.
- **진입 경로:** 전역 내비, 홈의 스토리 진입, 카테고리·토픽이 담긴 딥링크.
- **구성 · 주요 기능:**
  - **인트로:** 키커·제목·소개문.
  - **주요 영역:** 추천(주요) 글 큰 카드 + 옆에 "최신" 글 묶음. _(추천 글 선정·정렬 기준은 섹션7 참고)_
  - **카테고리 칩:** 카테고리 선택 줄("전체" 포함).
  - **토픽 태그:** 글들에 쓰인 토픽 태그 묶음(빈도순 정렬).
  - **글 그리드:** 현재 조건에 맞는 글 카드(추천 글은 그리드에서 제외).
  - **빈 상태:** 결과가 0개면 안내 제목·부연과 초기화 CTA.
  - **뉴스레터 구독 티저:** 목록 하단에 "More stories every week" 안내와 구독 버튼("Subscribe to Korea Story"). 동작은 섹션4.4.
- **정책 · 규칙:**
  - **단일 필터:** 카테고리와 토픽은 **동시에 하나만** 적용된다. 카테고리를 고르면 토픽이 해제되고, 토픽을 고르면 카테고리가 "전체"로 돌아간다. 같은 토픽을 다시 누르면 해제된다.
  - **딥링크 프리필:** 주소의 카테고리·토픽 값으로 초기 상태를 채운다.
- **상태별 표시:** 기본(전체) / 카테고리·토픽 적용 / 빈 상태(0건).

### 4.2 스토리 상세 - `/stories/[storyId]`

- **목적:** 한 글을 편히 읽고, 토픽·다음 스토리로 이어지게 한다.
- **진입 경로:** 목록 카드, 홈 카드, 토픽 태그, 공유·딥링크.
- **구성 · 주요 기능:**
  - **돌아가기:** 상단 돌아가기(브레드크럼).
  - **머리말:** 카테고리 배지 · 날짜 · 읽는 시간 / 제목 / 요약.
  - **대표 비주얼:** 색상 배경 블록(실제 사진 아님).
  - **본문:** 문단 단위 텍스트.
  - **토픽:** 글에 달린 토픽 태그(누르면 해당 토픽으로 목록 이동).
  - **다음 스토리:** 이 글의 컨셉(카테고리·토픽)과 맞는 다음 스토리 카드(최대 3개). 글을 읽은 흐름이 다음 글 읽기로 이어지게 한다.
- **정책 · 규칙:**
  - **다음 스토리 구성:** 글의 컨셉(카테고리·토픽)과 맞는 다음 스토리를 추천한다(최대 3개). 비슷한 주제가 없으면 최신 스토리로 채운다. 정확한 매칭 기준은 추후 정의(→ 섹션7).
  - **토픽 이동:** 토픽 태그를 누르면 그 토픽이 적용된 목록으로 이동한다.
  - **돌아가기 동작:** 블로그 글 목록으로 이동한다.
- **상태별 표시:** 정상 / **404(잘못된·없는 글)** → 섹션4.3.

### 4.3 없는 글 처리

- **목적:** 잘못된·삭제된 글 주소에서 막다른 길을 만들지 않는다.
- **정책 · 규칙:** 존재하지 않는 글 주소로 들어가면 404(찾을 수 없음) 페이지를 띄우고, 홈으로 가는 CTA를 보여준다. 페이지 제목도 "찾을 수 없음" 취지로 표기된다.
- **상태별 표시:** 없음(404 안내 + 홈 CTA).

### 4.4 뉴스레터 구독 (Korea Story)

- **목적:** 새 스토리를 계속 받아보려는 여행자를 뉴스레터 구독으로 연결한다.
- **진입 경로:** 스토리 목록 하단 구독 티저("More stories every week" + "Subscribe to Korea Story" 버튼).
- **구성 · 주요 기능:** 안내 문구 + 구독 버튼. 구독에 사용하는 이메일은 로그인 계정의 이메일을 사용한다(별도 이메일 입력 없음).
- **정책 · 규칙:**
  - 구독은 **로그인이 필요한 행동**이다. 비로그인 상태에서 구독 버튼을 누르면 **인증 게이트**가 발동한다(공통 모달). 인증 완료 후 **구독 버튼을 다시 눌러야** 구독이 처리된다. → [auth](./01_auth.md)
  - 로그인 상태에서 누르면 즉시 구독 처리되고 완료 안내(토스트 등)를 보여준다.
  - 구독 상태는 따로 저장되지 않으며, 같은 계정으로 다시 구독할 수 있다(열린 상태). "구독함" 같은 영속 상태로 잠기지 않는다.
- **상태별 표시:** 기본(구독 버튼) / 구독 완료(안내) / (비로그인) 인증 게이트.

## 6. 예외 처리 & 엣지 케이스

| 상황                       | 기대 동작                                                     |
| -------------------------- | ------------------------------------------------------------- |
| 카테고리·토픽 결과 0건     | 빈 상태 안내 + 초기화 CTA.                                    |
| 카테고리 선택 중 토픽 선택 | 토픽이 적용되고 카테고리는 "전체"로 전환(둘 동시 적용 안 됨). |
| 같은 토픽 재클릭           | 토픽이 해제되어 전체로 복귀.                                  |
| 다음 스토리가 없는 경우    | 비슷한 주제가 없으면 최신 스토리로 표시한다.                  |
| 잘못된/삭제된 글 주소      | 404(찾을 수 없음) 안내 + 홈 CTA.                              |
| 비로그인으로 구독 시도     | 인증 게이트 발동 → 인증 후 구독 버튼 재클릭으로 구독. 모달을 닫으면 구독되지 않는다. |
| 같은 계정으로 다시 구독    | 제한 없이 다시 구독할 수 있다(상태 저장 안 함).               |

## 7. TBD / 정책 공백

> 현재 비어 있는 기능 및 정책과 프로덕션 전환 시 결정이 필요한 항목. (결정권자 : CPO)

1. **참여 기능 미지원** : 현재는 댓글, 좋아요, 북마크, 실제 공유 등 사용자의 콘텐츠 참여 기능이 제공되지 않음. 향후 이러한 기능의 도입 및 우선순위에 대한 검토가 필요함.
2. **글 하단 연계(다음 스토리/관련 경험)** : MVP에서는 글 하단에 컨셉이 맞는 다음 스토리(최대 3개)를 노출해 읽기 흐름을 이어 간다. 다음 스토리 선정·매칭 기준(같은 카테고리·토픽 우선, 부족하면 최신으로 보완)의 구체화가 필요함. 추후 블로그 글 유입을 서비스 이용 전환으로 잇기 위해, 글 하단을 연관성 높은 경험 목록(→ [experience](./04_experience.md)) 노출로 바꾸거나 함께 노출하는 방식을 검토함.
3. **스토리 큐레이션 및 정렬 정책** : 추천(주요) 글은 현재 수동으로 지정하며, 목록은 고정된 순서로 노출됨. 앞으로 어떤 기준(큐레이션, 인기, 최신 등)에 따라 글을 추천·정렬할지에 대한 세부 정책 및 시스템화 필요.
4. **추천 글 중복 노출 정책** : 추천(주요)으로 강조된 글을 하단 글 목록(그리드)에 중복하여 노출할지 여부에 대한 정책 및 기준 확정 필요.
5. **SEO 및 공유용 메타데이터** : 검색 유입과 외부 공유를 고려하여, 각 글에 제목, 요약, OG(Open Graph) 태그 등 SEO 및 소셜 미디어 전용 메타데이터 설정 정책이 필요함. (구현 시점에 구체 가이드 작성 필요)
