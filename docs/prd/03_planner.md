# AI 일정 플래너 (Planner) ★

**한 줄 요약:** 여행자가 도시·날짜·인원·관심사·교통·예산을 입력하면 다일차 일정을 자동 생성하고, 일자별 장소·이동·숙박·비용을 보여주며 저장·공유·관리하게 한다. (플래그십)

| --- | --- |
| **상태** | 🟡 초안(검토 요청) |
| **작성 기준** | 현재 구현된 동작 기준 (미구현·정책 공백은 §7에 분리) |

## 1. 기능 배경 및 목적

### 배경 / 문제
한국 자유여행 계획은 "어디를 어떤 순서로, 하루에 얼마나, 얼마 들지"를 직접 짜야 해 부담이 크다. Handled의 차별점은 이 계획 과정을 **자동 초안**으로 대신해 주는 것이다.

### 목적 / 목표
- **입력 → 초안:** 최소 입력(도시·날짜·관심사)만으로 시간대별 슬롯이 채워진 다일차 일정을 즉시 만든다.
- **의사결정 지원:** 일자별 동선·이동수단·숙박·**예상 비용**을 한 화면에서 보여 "이 여행이 어떤 모습·얼마인지" 감을 준다.
- **지속·확산:** 일정을 저장해 다시 보고, 공유하며, 관련 경험으로 연결한다.

### 성공의 정의 · 비목표(Non-goals)
- **성공:** 여행자가 위저드를 완료 → (필요 시 1회 인증) → 일정 결과에 도달하고, 저장해 내 일정에서 다시 본다.
- **비목표(이번 범위 밖):** 실제 예약·확정 견적, 좌표 기반 실지도 경로, 일정 입력 사후 편집, 슬롯 재생성/잠금 UI, 크레딧 과금. (→ §7)

> **결과물의 성격:** 생성된 일정의 장소·비용·이동은 **대표 추정·예시**이며 입력값과 1:1로 분해되는 확정 데이터가 아니다. 실제 예약/견적이 아니라 *계획 초안*으로 다룬다.

## 3. 핵심 사용자 플로우

**A. 생성**
1. 위저드 진입(홈 CTA·내비·딥링크) → ①목적지·날짜·인원 → ②관심사·교통·예산 → ③검토.
2. 생성 누름 → 비로그인이면 인증(→ [auth](./01_auth.md)) → 생성 진행(짧은 대기) → **결과 캔버스**로 이동.

**B. 결과 탐색 → 저장/공유**
1. (다일차면) 일자 탭 전환 → 슬롯·이동·숙박·일자 합계·총비용 확인.
2. 관련 추천 경험 확인(→ [experience](./04_experience.md)).
3. 저장 또는 공유.

**C. 관리**
1. 저장한 일정은 내 일정에서 관리한다(예정/지난, 열기·삭제 → [my-plans](./06_my-plans.md)).

## 4. 화면별 기능 정의 및 정책

### 4.1 일정 생성 위저드 - `/plan/new` (3단계)
- **목적:** 최소 입력으로 일정 생성에 필요한 조건을 받는다.
- **진입 경로:** 홈/내비 CTA, 딥링크(도시·시작·종료일 프리필).
- **구성 · 주요 기능 (단계별):**
  - **1단계 - 목적지·날짜·인원:** 도시 선택 / 여행 기간 선택 / 인원 카운터(성인·청소년·아동).
  - **2단계 - 관심사·교통·예산:** 관심사 선택(최대 3개) / 교통수단(대중교통·택시·자가용, 선택) / 예산 슬라이더.
  - **3단계 - 검토:** 입력 요약 + 크레딧 안내 후 생성.
  - 상단에 3단계 진행 표시(완료 시 체크).
- **정책 · 규칙:**
  - **도시:** 플래너는 **10개 도시**를 제공한다(경험 탐색의 도시 필터 4곳과 별개). 단, 실제 장소·호텔 데이터는 서울 등 일부 도시 중심이며 그 외는 일반 일정으로 대체된다. → §7
  - **여행 기간:** 최대 **5일**. 기본값은 (오늘+7일)부터 1박 2일. 종료일은 시작일 이후여야 한다.
  - **인원:** 성인 최소 1명. 청소년·아동은 0부터.
  - **관심사:** 최소 1개 있어야 다음 단계로 진행, **최대 3개**까지 선택. (8개 관심사 옵션)
  - **교통수단:** 선택(미선택 시 대중교통 가정).
  - **예산:** 인원(성인+청소년, **아동 제외**)과 기간으로 최소·최대·기본값을 자동 산정한다. 슬라이더를 직접 조작하기 전에는 인원·기간 변경에 따라 기본값이 자동으로 따라오고, 조작 이후에는 사용자 값을 유지하되 범위 안으로 맞춘다.
  - **유효성:** 1단계(도시+유효 기간+성인≥1), 2단계(관심사≥1)를 충족해야 다음으로 넘어간다.
- **상태별 표시:** 단계별 입력 / 비활성(다음 버튼) / 생성 중(스플래시).

### 4.2 생성 실행 & 인증 게이트
- **목적:** 검토 후 생성을 실행하되, 비로그인 사용자를 흐름 중단 없이 인증시킨다.
- **정책 · 규칙:**
  - 생성 누름 → **비로그인이면 인증 요구 모달**, 인증 완료 시 **동일 입력으로 생성이 자동 진행**된다. → [auth](./01_auth.md)
  - 생성 중에는 짧은 대기(스플래시) 후 결과 캔버스로 이동하며, 생성된 일정은 저장소에 보관된다.
  - **크레딧:** 검토 단계에서 "생성에는 크레딧이 쓰인다"는 취지를 안내하지만, **실제로는 차감되지 않으며 잔량과 무관하게 생성된다.** → §7
- **상태별 표시:** 대기(스플래시, 진행 안내) / 인증 모달 / 완료(이동).

### 4.3 일정 결과 캔버스 - `/plan/[planId]`
- **목적:** 생성된 일정을 일자별로 보여주고 저장·공유·추천 연결을 제공한다.
- **진입 경로:** 생성 직후 자동 이동, 내 일정에서 열기, 공유 링크.
- **구성 · 주요 기능:**
  - **헤더:** 일정 이름 / (저장된 경우) 저장 배지 / 공유 버튼 / 위저드로 돌아가기.
  - **요약:** 도시 · 기간 · 인원 · **예상 총비용**(추정 안내 동반) · 교통 배지 · 관심사 칩.
  - **지도:** 활성 일자의 동선 미리보기(데모 표기).
  - **일자 탭:** 다일차면 일자별 탭(탭에 일자 합계 표시).
  - **활성 일자 패널:** 일자 제목·합계 / 숙박 카드(해당 시) / 시간대 슬롯 카드(카테고리·장소·시간·비용·메모) / 슬롯 사이 이동 구간(수단·소요·요금) / 일자 합계(활동+교통, 숙박 포함).
  - **총비용 카드:** 전체 일자 합계 + 일자별 내역.
  - **저장:** 저장 콜아웃 + 하단 고정 저장 바(추천 영역이 보이거나 이미 저장 시 숨김) → 저장 완료 모달.
  - **추천 경험:** 일정 도시·관심사 기반 추천 카드 + "전체 보기"(경험 탐색).
- **정책 · 규칙:**
  - **비용은 렌더 시점에 추정**되며 일정에 저장되지 않는다(통화: 원화 기준, 표시 시 로케일에 따라 환산). 마지막 날은 숙박이 없다. 상세 규칙은 [비용 상세 문서](../plan-cost-detail-requirements.md).
  - **저장 vs 생성:** 생성된 일정은 저장소에 보관되지만, 사용자가 **저장**을 눌러야 "저장됨"으로 표시되고 **내 일정 목록에 나타난다.**
  - **공유:** 기기 공유 시트가 있으면 그것으로, 없으면 링크를 복사한다(완료/실패 토스트). *단, 현재 공유 링크는 생성자 브라우저에 저장된 일정을 가리켜 다른 기기·사용자에게는 열리지 않는다.* → §7
  - **재생성·슬롯 잠금:** 현재 결과 화면에 노출되지 않는다(생성 엔진은 지원하나 UI 미연결). → §7
- **상태별 표시:** 로딩 / 정상 / **없음(잘못된·삭제된 일정)** → 안내 + 생성 CTA.

### 4.4 저장 일정 관리 (`/my-plans`) - 이관됨
저장한 일정의 목록·예정/지난 구분·열기·삭제 등 `/my-plans` 페이지는 [06_my-plans](./06_my-plans.md)에서 다룬다. 결과 캔버스의 **저장 동작 자체**(저장 버튼·저장됨 배지)는 §4.3에 있다.

### 4.5 일정 생성·비용 산정 정책 (요약)
> 제품 정책 관점의 요약이다. 정확한 수치·산식은 [비용 상세 문서](../plan-cost-detail-requirements.md) 및 후속 논의(§7)를 따른다.
- **하루 구성:** 하루를 오전·점심·오후·저녁 **4개 시간대 슬롯**으로 채운다.
- **카테고리 선택:** 슬롯은 선택한 관심사를 우선 반영하되 시간대에 맞는 카테고리(예: 점심=식사, 저녁=야간/식사)에서 고른다.
- **연령 안전장치:** 청소년·아동이 있으면 **야간(Nightlife) 카테고리를 자동 제외**한다.
- **장소 매칭:** 슬롯에는 도시별 실제 장소를 우선 넣고, 데이터가 없으면 일반 일정 단계로 대체한다(서울 중심 커버리지).
- **비용 추정:** 카테고리·교통수단·예산대(tier)로 활동·이동·숙박 비용을 추정한다. 활동·이동은 인원수에 비례, 숙박은 1박 단위.

| AC-PLAN-02 | US-PLAN-02 | 2단계에서 관심사를 최소 1개·최대 3개까지 고를 수 있고, 인원·기간에 따라 예산 범위와 기본값이 자동으로 맞춰진다. |
| AC-PLAN-03 | US-PLAN-03 | 3단계에서 도시·날짜·인원·관심사·교통·예산이 요약으로 표시된 뒤 생성할 수 있다. |
| AC-PLAN-04 | US-PLAN-01 | 생성하면 여행 기간만큼의 일자가 만들어지고, 각 일자는 시간대별 슬롯(장소·시간·카테고리)으로 채워져 결과 화면으로 이동한다. |

| AC-PLAN-10 | US-PLAN-07 | 공유를 누르면 기기 공유 시트 또는 링크 복사로 일정 주소를 공유할 수 있다(복사 시 안내 표시). |

## 6. 예외 처리 & 엣지 케이스

| 상황 | 기대 동작 |
|---|---|
| 여행 기간 5일 초과 선택 | 최대 5일로 제한된다. |
| 종료일이 시작일보다 빠름 | 유효하지 않아 다음 단계로 진행되지 않는다. |
| 관심사 0개 / 3개 초과 시도 | 0개면 진행 불가, 상한(3개) 도달 시 추가 선택이 막힌다. |
| 청소년·아동 포함 | 야간 카테고리가 자동 제외된다. |
| 예산 미조작 상태에서 인원·기간 변경 | 기본값이 새 조건에 맞게 자동 갱신된다(조작 후에는 범위 내로만 보정). |
| 비로그인으로 생성 시도 | 인증 모달 → 인증 후 자동 생성. 모달을 닫으면 생성되지 않는다. |
| 당일(1일) 일정 | 일자 탭이 없고, 마지막 날 규칙상 숙박이 표시되지 않는다. |
| 장소 데이터가 없는 도시 | 일반 일정 단계로 대체되어 빈 슬롯 없이 채워진다. |
| 공유 시트 미지원 | 링크가 클립보드로 복사되고 안내 토스트가 뜬다(실패 시 에러 토스트). |
| 공유 링크를 다른 기기/사용자가 열기 | 현재는 일정을 찾지 못해 "없음" 화면이 보인다(기기 종속 저장). → §7 |
| 생성만 하고 저장 안 한 일정 | 저장소엔 남지만 내 일정 목록에는 보이지 않는다. |
| 크레딧 0인 사용자의 생성 | 현재 차단되지 않고 생성된다(차감 로직 없음). → §7 |

## 7. TBD / 정책 공백

> 현재 비어 있는 정책과 프로덕션 전환 시 결정할 항목. (결정권자·기한: _TBD_)

1. **크레딧 미차감 (중요)** - 생성 시 크레딧이 차감되지 않아 사실상 무제한 생성된다. 차감 규칙·소진 UX·충전 정책 필요. ([auth](./01_auth.md)와 공유 이슈)
2. **일정-계정 비연동 (중요)** - 저장 일정이 계정이 아니라 기기/브라우저에 묶인다. 계정 기반 저장·기기 간 동기화 정책 필요. ([auth](./01_auth.md)와 공유)
3. **공유가 실제로 동작하지 않음 (중요)** - 공유 링크가 생성자 브라우저의 일정을 가리켜 타인/타기기에서 열리지 않는다. 서버 저장·공유 링크 정책 필요.
4. **재생성·슬롯 잠금 UI 부재** - 생성 엔진은 전체/슬롯 단위 재생성과 잠금을 지원하나 결과 화면에 노출되지 않는다. 노출 여부·상호작용 정책 필요.
5. **일정 입력 사후 편집 부재** - 내 일정의 "편집"은 결과 열기로 동작하며, 입력(날짜·인원 등)을 고쳐 다시 생성하는 경로가 없다.
6. **도시 커버리지 편중** - 10개 목적지를 제공하나 실제 장소·호텔 데이터는 서울 등 일부 중심이고 나머지는 일반 대체다. 타 도시 장소 풀 확충 정책 필요.
7. **비용의 성격** - 비용은 추정치이며 저장되지 않고, 실제 예약/확정 견적이 아니다. 프로덕션에서 AI/실데이터가 수치를 채우는 방식·정확도 기준 필요.
8. **지도는 데모** - 실제 좌표·경로 기반이 아니다. 실지도/경로 연동 정책 필요.
9. **결과의 AI 생성 특성** - 장소·비용은 대표 예시로, 입력과 1:1로 분해되지 않는다. 사용자 기대를 관리할 표기·카피 정책 필요.
10. **추천 경험 출시 전 연계** - 추천을 열어도 현재는 예약이 불가하다(경험 출시 전: [experience](./04_experience.md)).
