# 03. AI 일정 플래너 (Planner)

여행자가 도시·날짜·인원·관심사·교통·예산을 입력하면 다일차 일정을 자동 생성하고, 일자별 장소·이동·숙박·비용을 보여주며 저장·공유·관리하게 한다.

| **작성 기준**   | 현재 구현된 동작 기준 (미구현·정책 공백은 섹션7에 분리)                                                                                                                                                                           |

## 1. 기능 배경 및 목적

### 배경 / 문제

한국 자유여행 계획은 "어디를 어떤 순서로, 하루에 얼마나, 얼마 들지"를 직접 짜야 해 부담이 크다. Handled의 차별점은 이 계획 과정을 **자동 초안**으로 대신해 주는 것이다.

### 목적 / 목표

- **입력 → 초안:** 최소 입력(도시·날짜·관심사)만으로 시간대별 슬롯이 채워진 다일차 일정을 즉시 만든다.
- **의사결정 지원:** 일자별 동선·이동수단·숙박·**예상 비용**을 한 화면에서 보여 "이 여행이 어떤 모습·얼마인지" 감을 준다.
- **지속·확산:** 일정을 저장해 다시 보고, 공유하며, 관련 경험으로 연결한다.

### 성공의 정의 · 비목표(Non-goals)

- **성공:** 여행자가 위저드를 완료 → (필요 시 1회 인증) → 일정 결과에 도달하고, 저장해 내 일정에서 다시 본다.
- **비목표(이번 범위 밖):** 실제 예약·확정 견적, 좌표 기반 실지도 경로, 일정 입력 사후 편집, 슬롯 재생성/잠금 UI, 크레딧 과금. (→ 섹션7)

> **결과물의 성격:** 생성된 일정의 장소·비용·이동은 **대표 추정·예시**이며 입력값과 1:1로 분해되는 확정 데이터가 아니다. 실제 예약/견적이 아니라 *계획 초안*으로 다룬다.

## 3. 핵심 사용자 플로우

**A. 생성**

1. 위저드 진입(홈 CTA·내비·딥링크) → ①목적지·날짜·인원 → ②관심사·교통·예산 → ③검토.
2. 생성 누름 → 비로그인이면 인증(→ [auth](./01_auth.md)) → 생성 진행(짧은 대기) → **결과 캔버스**로 이동.

**B. 결과 탐색 → 저장/공유**

1. (다일차면) 일자 탭 전환 → 슬롯·이동·숙박·일자 합계·총비용 확인.
2. 관련 추천 경험 확인(→ [experience](./04_experience.md)).
3. 저장 또는 공유.

**C. 관리**

1. 저장한 일정은 내 일정에서 관리한다(예정/지난, 열기·삭제 → [my-plans](./06_my-plans.md)).

## 4. 화면별 기능 정의 및 정책

### 4.1 일정 생성 위저드 - `/plan/new` (3단계)

- **목적:** 최소 입력으로 일정 생성에 필요한 조건을 받는다.
- **진입 경로:** 홈/내비 CTA, 딥링크(시작·종료일 프리필).
- **구성 · 주요 기능 (단계별):**
  - **1단계 - 목적지·날짜·인원:** 도시 선택 / 여행 기간 선택 / 인원 카운터(성인·청소년·아동).
  - **2단계 - 관심사·교통·예산:** 관심사 선택(최대 3개) / 교통수단(대중교통·택시·자가용, 선택) / 예산 슬라이더.
  - **3단계 - 검토:** 입력 요약 + 크레딧 안내 후 생성.
  - 상단에 3단계 진행 표시(완료 시 체크).
- **정책 · 규칙:**
  - **도시:** 플래너는 **10개 도시**를 제공한다. (\* 구현에 따라 수정 가능 섹션 7참고)
    - 도시 목록 : 서울(Seoul), 부산(Busan), 인천(Incheon), 대구(Daegu), 대전(Daejeon), 광주(Gwangju), 울산(Ulsan), 수원(Suwon), 제주(Jeju), 강릉(Gangneung)
  - **여행 기간:** 최대 **5일**. 기본값은 (오늘+7일)부터 2박 3일. 종료일은 시작일 이후여야 한다.
  - **인원:** 성인 최소 1명. 청소년·아동은 0부터.
  - **관심사:** 최소 1개 있어야 다음 단계로 진행, **최대 3개**까지 선택. (8개 관심사 옵션)
  - **교통수단:** 대중교통, 택시, 자가용(개인차량 or 기사).
  - **예산:** 인원(성인+청소년, **아동 제외**)과 기간으로 최소·기본·최대값을 자동 산정한다. 산정 기준은 아래와 같다(한국 통화 원화 기준, 다국 통화는 환율 정의 후 반영 필요 → 섹션7).
    - **최소값** = 인원 수(아동 제외) × 일수 × 100,000원 × 1.3
    - **기본값** = 최소값 × 2
    - **최대값** = 최소값 × 5
    - 슬라이더를 직접 조작하기 전에는 인원·기간 변경에 따라 기본값이 자동으로 따라오고, 조작 이후에는 사용자 값을 유지하되 범위 안으로 맞춘다.
  - **유효성:** 1단계(도시 + 유효 기간 + 성인≥1), 2단계(관심사≥1)를 충족해야 다음으로 넘어간다.
- **상태별 표시:** 단계별 입력 / 비활성(다음 버튼) / 생성 중(스플래시).

### 4.2 생성 실행 & 인증 게이트

- **목적:** 검토 후 생성을 실행하되, 비로그인 사용자를 흐름 중단 없이 인증시킨다.
- **정책 · 규칙:**
  - 생성 누름 → **비로그인이면 인증 요구 모달**, 인증 완료 시 **동일 입력으로 생성이 자동 진행**된다. → [auth](./01_auth.md)
  - 생성 중에는 짧은 대기(스플래시) 후 결과 캔버스로 이동하며, 생성된 일정은 저장소에 보관된다.
  - **크레딧:** 검토 단계에서 "생성에는 크레딧이 쓰인다"는 정책을 안내한다.
- **상태별 표시:** 대기(스플래시, 진행 안내) / 인증 모달 / 완료(이동).

### 4.3 일정 결과 캔버스 - `/plan/[planId]`

- **목적:** 생성된 일정을 일자별로 보여주고 저장·공유·추천 연결을 제공한다.
- **진입 경로:** 생성 직후 자동 이동, 내 일정에서 열기, 공유 링크.
- **구성 · 주요 기능:**
  - **헤더:**
    - 일정 이름
    - (저장된 경우) 저장 배지
    - 공유 버튼
    - 위저드로 돌아가기.
  - **요약:** 도시 · 기간 · 인원 · **예상 총비용**(추정 안내 동반) · 교통 배지 · 관심사 칩.
  - **지도:** 활성 일자의 동선 미리보기(데모 표기).
  - **일자 탭:** 다일차면 일자별 탭(탭에 일자 합계 표시).
  - **활성 일자 패널:**
    - 일자 제목·합계
    - 숙박 카드(해당 시)
    - 시간대 슬롯 카드(카테고리·장소·시간·비용 등)
    - 슬롯 사이 이동 구간(수단·소요·요금)
    - 일자 합계(활동+교통, 숙박 포함)
  - **총비용 카드:** 전체 일자 합계 + 일자별 내역.
  - **저장:** 저장 콜아웃 + 하단 고정 저장 바(추천 영역이 보이거나 이미 저장 시 숨김) → 저장 완료 모달.
  - **추천 경험:** 일정 도시·관심사 기반 추천 카드 + "전체 보기"(경험 탐색).
- **정책 · 규칙:**
  - **저장 vs 생성:** 생성된 일정은 저장소에 보관되지만, 사용자가 **저장**을 눌러야 "저장됨"으로 표시되고 **내 일정 목록에 나타난다.**
  - **공유:** 기기 공유 시트가 있으면 그것으로, 없으면 링크를 복사한다(완료/실패 토스트).
- **상태별 표시:** 로딩 / 정상 / **없음(잘못된·삭제된 일정)** → 안내 + 홈 CTA.

### 4.4 저장 일정 관리 (`/my-plans`) - 이관됨

저장한 일정의 목록·예정/지난 구분·열기·삭제 등 `/my-plans` 페이지는 [06_my-plans](./06_my-plans.md)에서 다룬다. 결과 캔버스의 **저장 동작 자체**(저장 버튼·저장됨 배지)는 섹션4.3에 있다.

### 4.5 일정 생성·비용 산정 정책

> 제품 정책 관점의 요약이다. 정확한 수치·산식은 후속 논의(섹션7)를 따른다.

- **하루 구성:** 하루를 오전·점심·오후·저녁 **4개 시간대 슬롯**으로 채운다.
- **카테고리 선택:** 슬롯은 선택한 관심사를 우선 반영하되 시간대에 맞는 카테고리(예: 점심=식사, 저녁=야간/식사)에서 고른다.
- **장소 매칭:** 슬롯에는 도시별 실제 장소를 우선 넣고, 데이터가 없으면 일반 일정 단계로 대체한다(선택한 도시 중심 커버리지).
- **비용 추정:** 카테고리·교통수단·예산대(tier)로 활동·이동·숙박 비용을 추정한다. 활동·이동은 인원수에 비례, 숙박은 1박 단위.

## 6. 예외 처리 & 엣지 케이스

| 상황                                | 기대 동작                                                                                                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 여행 기간 5일 초과 선택             | 최대 5일로 제한된다.                                                                                                                                         |
| 종료일이 시작일보다 빠름 시도       | 사용자가 잘못 입력할 경우 종료일을 시작일로 맞추거나 초기화하여 잘못된 입력을 막고, 시스템적으로 이상 값이 들어간 경우에는 다음 단계로 진행되지 않도록 한다. |
| 관심사 0개 / 3개 초과 시도          | 0개면 진행 불가, 상한(3개) 도달 시 추가 선택이 막힌다.                                                                                                       |
| 예산 미조작 상태에서 인원·기간 변경 | 기본값이 새 조건에 맞게 자동 갱신된다(조작 후에는 범위 내로만 보정).                                                                                         |
| 비로그인으로 생성 시도              | 인증 모달 → 인증 후 자동 생성. 모달을 닫으면 생성되지 않는다.                                                                                                |
| 당일(1일) 일정                      | 일자 탭이 없고, 마지막 날 규칙상 숙박이 표시되지 않는다.                                                                                                     |
| 장소 데이터가 없는 도시             | 일반 일정 단계로 대체되어 빈 슬롯 없이 채워진다.                                                                                                             |
| 생성만 하고 저장 안 한 일정         | 시스템 저장소엔 남지만 내 일정 목록에는 보이지 않는다.                                                                                                       |
| 크레딧 0인 사용자의 생성            | 생성을 시도하지 않고, 크레딧 충전을 유도한다.                                                                                                                |

## 7. TBD / 정책 공백

> 현재 비어 있는 기능 및 정책과 프로덕션 전환 시 결정이 필요한 항목. (결정권자 : CPO)

- **검토 필요 사항**
  1. **기본 여행 기간 세팅 값 정의 필요:** 현재 오늘 날짜 기준 7일 이후를 시작일로 설정 후 2박 3일 세팅인데, 이를 유지할지 또는 더 늘릴지 결정 필요.
  2. **공유 기획 필요:** 특정 형태(PDF, IMG 등)로 공유가 가능하도록 할지, 혹은 링크 형태로 제공하여 해당 링크 접속 시 일정 상세 보기 화면을 제공할지 결정 필요.
  3. **지도 연동:** 실지도/경로 연동 정책 수립 필요.
  4. **알림/리마인더:** 출발 전 및 일정 당일에 제공되는 알림, 결제 알림, 리마인더 등 별도 알림 기능 도입 여부와 정책 수립이 필요. (해당 알림 기능은 플래너에만 한정되지 않으므로, 별도 기획 필요)

- **MVP 제외 (\* 향후 고도화)**
  1. **생성 후 편집:** 장소 교체·삭제·순서 변경·고정·슬롯 단위 재생성. MVP에는 제외하고, 향후 고도화 스펙으로 진행.
  2. **멀티시티/도시 간 이동:** 현재 1일정=1도시 구조이나, 서울+부산+제주처럼 다도시 일정과 KTX·국내선 등 도시 간 이동 반영 여부 검토 필요.
  3. **예약 핸드오프:** 일정 항목(숙박·식당·교통·티켓)에서 실제 예약으로 가는 경로. MVP에는 제외하고, 향후 고도화 스펙으로 진행(경험 예약은 [experience](./04_experience.md) 참고).
  4. **동행자 공동 편집:** 여러 사람이 한 일정을 함께 편집. MVP에는 제외하고, 향후 고도화 스펙으로 진행.
  5. **입력 선호 확장:** 페이스(여유/빡빡), 식이(할랄·채식 등), 접근성·이동약자, 여행자 유형(커플/가족/친구) 등 선호 입력 확장. MVP에는 제외하고, 향후 고도화 스펙으로 진행.
