# PRD 라벨링 패스: $ARGUMENTS

너는 지금 **읽기 전용 검증자**다. 대상 PRD 문서(`$ARGUMENTS`)의 모든 동작 주장을 실제 프로토타입 코드(`app/`, `i18n/`, `messages/`, `DESIGN.md`)에 대조해 판정하고, 그 결과를 `docs/prd/_verify/ledger.md`에 추가한다.

**PRD 본문은 절대 수정하지 않는다.** 이 패스의 산출물은 원장뿐이다. 코드 참조(`파일:줄`)는 원장에만 남기고 PRD 본문으로 옮기지 않는다.

## 전제: 이 PRD는 프로토타입 거울이 아니라 개발 핸드오프 문서다

프로토타입은 컨셉 증명용이고, 이 문서는 실제 구현을 위해 개발자에게 넘기는 사양서다. 따라서 코드에 없는 서술도 "제품화를 위해 의도된 요소"라면 허용된다. 진짜 리스크는 _"아직 의도일 뿐인 것을 이미 구현된 현재 동작인 양 서술"_ 하거나 그 반대다. 그래서 코드 대조는 결함 판정이 아니라 **정직한 라벨링**이 목적이다.

## 판정 4종

- **근거있음**: 코드에 실재. "현재 동작"으로 서술 가능. → 유지
- **확장**: 코드엔 없지만 제품화 의도. 허용되나 "현재 동작"인 척하면 안 됨(시제·섹션·라벨 점검). → 당신 확인
- **오표기**: 코드와 다른데 "현재 동작"으로 단언 / 프로토타입 임시방편을 제품 사양처럼 서술 / 비기능 스텁을 기능인 양 나열. → Claude가 잡고 당신 승인
- **열린정책**: 섹션7 TBD. 결정 필요. → 당신/CPO 결정 큐

## 심각도

- 🔴 치명: 개발자가 잘못 구현하게 만드는 오표기(현재 동작 단언이 코드와 반대 / 핵심 정책 누락)
- 🟠 주요: 의미 있는 불일치·누락 또는 CPO가 반드시 결정할 정책 공백
- 🟡 경미: 작은 표현·범위 부정확, 비기능 스텁 미표기
- ⚪ 문체: 규약 위반(대시·ID 체계·깨진 링크) 또는 가독성

**노이즈 플로어: 경미까지 모두 잡는다.**

## 검증 5축 (전수 점검)

1. **코드 정합성** (주축): 모든 동작 주장을 코드에서 근거 찾아 4종 라벨링. 근거는 `파일:줄`.
2. **내부 일관성**: 모든 AC가 실재 US를 가리키는가, 교차 참조 링크가 살아있는가, 용어집 단어를 일관되게 쓰는가.
3. **규약 준수**: README 작성 규약 - 대시 금지(하이픈만), 페르소나 단일화("여행자로서"), 메타 헤더 포맷, 섹션7 구조, ID 체계(`US-도메인-NN`/`AC-도메인-NN`).
4. **커버리지 완전성**: 화면↔도메인 매핑의 해당 라우트가 빠짐없이 다뤄지는가. **단 의도적 제외(checkout 보류·guide 현 단계 제외)는 누락이 아니라 정상 - 결함으로 잡지 말 것.**
5. **CPO 적합성**: 섹션7이 CPO가 결정할 항목을 제품 임원 언어로 드러내는가.

## 결정자

`Claude자동` 승인만 / `당신` 제품 의도 판단 / `CPO` 정책 결정 큐.

## 절차

1. `$ARGUMENTS` 와 `docs/prd/README.md`(규약·용어집·매핑)를 읽는다.
2. PRD의 동작 주장을 섹션4·섹션5 중심으로 추출한다.
3. 각 주장을 `app/` 코드에서 grep/read로 근거를 찾아 4종으로 판정한다. **근거 없이 "근거있음"으로 단정하지 말 것** - 못 찾으면 "확장" 또는 "확인 필요"로 둔다.
4. 5축을 모두 훑어 누락·규약 위반도 잡는다.
5. `docs/prd/_verify/ledger.md` 끝에 `## <파일명> 원장` 섹션을 추가한다. 같은 표 컬럼을 쓴다:
   `| ID | 위치 | 축 | 판정 | 심각도 | 근거 (원장 한정) | 제안 조치 | 결정자 |`
   ID는 `L-<도메인>-NN`. 섹션 끝에 **관찰 메모**(본문 충실도 총평, 확장/오표기 패턴, 타 문서와 중복되는 열린정책)를 붙인다.
6. 마지막에 이 문서의 요약(근거있음 N · 확장 N · 오표기 N[심각도 분포] · 열린정책 N)을 한 줄로 보고한다.

코드로 판정 불가한 의도/정책 문장은 억지로 확정하지 말고 "확장" 또는 "열린정책"으로 정직하게 분류한다.
